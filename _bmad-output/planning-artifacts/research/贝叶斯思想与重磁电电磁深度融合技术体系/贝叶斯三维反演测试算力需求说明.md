## 一、项目计算特点

`★ Insight ─────────────────────────────────────`
**项目计算特点分析**：
1. **计算密集型**：MCMC采样、3D正演、POD降维都是大规模矩阵运算
2. **GPU友好**：并行采样、PINN训练可充分利用GPU加速
3. **内存敏感**：峰值内存由网格、场变量、并发、预条件器、通信和checkpoint共同测量，不预设容量。
`─────────────────────────────────────────────────`

### 核心算法

| 算法模块 | 计算特点 | GPU加速潜力 |
|---------|---------|------------|
| **贝叶斯推断** | 大规模矩阵运算、高维积分 | ★★★★★ |
| **MCMC采样** | 并行链、可并行似然计算 | ★★★★★ |
| **POD降维** | SVD分解、特征值计算 | ★★★★ |
| **PINN代理模型** | 神经网络训练 | ★★★★★ |
| **3D正演模拟** | 有限差分/有限元 | ★★★★ |

### 技术栈

- **计算框架**：Python (NumPy/SciPy)、PyTorch、JAX
- **GPU加速**：CUDA、DCU (国产)、ROCm (AMD)
- **分布式**：Ray、MPI
- **桌面端**：PyQt6
- **云端**：FastAPI + Kubernetes

## 三、使用方式选择

### 推荐：SLURM 作业调度

**理由**：
1. **适合批处理计算**：实际运行时长由工作负载与诊断合同测量。
2. **隔离候选**：是否独占、队列策略和可复现条件须由部署记录、环境锁定与运行 manifest 证明；本文不作资源独占承诺。
3. **成本可审计**：保存实际计费清单、失败重复与调参成本。
4. **硬件适配**：调度器与平台能力须在部署前以文档和兼容性试验确认。

**示例 SLURM 脚本**：

<pre data-wp5-code-block="COMPUTE-03" data-language="bash" data-capability-status="not-executable" data-test-evidence="none">
#!/bin/bash

#SBATCH --partition=gpu
#SBATCH --nodes=<registered-nodes>
#SBATCH --ntasks-per-node=<registered-tasks>
#SBATCH --cpus-per-task=<registered-cpus>
#SBATCH --gres=gpu:<registered-gpus>
#SBATCH --mem=<registered-memory>    # 项目登记的内存请求
#SBATCH --time=<registered-walltime> # 项目登记的墙钟上限

## 五、测试目的与成功标准

| 测试类别 | 目的 | 成功标准 |
|---------|------|---------|
| **功能验证** | 算法在云端环境正确运行 | 按风险ID、独立oracle与预注册数值容差判定 |
| **性能验证** | 验证GPU加速效果 | 报告同精度time-to-accuracy及区间，不设固定倍数 |
| **稳定性验证** | 长时间运行与恢复 | 按风险暴露时长、故障注入和恢复不变量设计 |
| **成本验证** | 验证云端计算性价比 | 达到预注册精度与诊断门后，按manifest计费清单报告 |
| **兼容性验证** | 国产硬件适配验证 | 由兼容性manifest记录可用性、限制与失败路径 |

### 详细成功标准

**功能验证**：
- [ ] 风险登记中的可达分支、物理不变量与独立oracle均按预注册容差报告
- [ ] 合成任务的误差、校准与失败处置按冻结功能量回写
- [ ] 跨环境一致性由相同输入、版本与数值容差的可复算比较判定

**性能验证**：
- [ ] 单GPU MCMC按 ESS/s/GPU 与关键决策量 MCSE 报告
- [ ] 4GPU按统一精度预算报告强/弱扩展及置信区间
- [ ] POD按独立留出误差、覆盖率变化与二阶段校正验收

**稳定性验证**：
- [ ] 暴露时长由风险模型确定并绑定环境/工作负载
- [ ] 检查点恢复以预注册故障集合、状态不变量和失败处置验收
- [ ] 内存泄漏检测通过

**成本验证**：
- [ ] 单次反演保存提交日报价、实际卡时及完整计费清单
- [ ] 大规模联合保存失败重复和调参成本，不做选择性删除

计算:
- 卡时 = manifest中的实际卡数 × 可审计运行小时
- 费用 = 实际卡时 × 提交日计费清单单价

存储、网络和总价：`PENDING/null`。仅可由提交日计费清单、实际用量与 benchmark manifest 计算；不得在本文保留固定容量、时长、单价或总价。
</pre>

## 七、SCNet 特别注意事项

### 1. 国产芯片适配

**当前状态**：项目主要针对 NVIDIA GPU 优化，国产芯片需额外适配工作

**适配优先级**：
1. **DCU (曙光)** - 市场占有率较高，优先适配
2. **昇腾 (华为)** - 生态较完善
3. **海光** - 兼容性较好，适配成本较低

### 2. 数据传输

**大文件传输建议**：
<pre data-wp5-code-block="COMPUTE-10" data-language="bash" data-capability-status="not-executable" data-test-evidence="none">
# 分片压缩
tar -czf - data/ | split -d -b 1G - data.tar.gz.

# 并行传输
rsync -avz --progress data/ user@scnet:/scratch/

# 使用传输加速工具
# (如 bbcp, globus-url-copy)
</pre>

### 3. 作业队列

**GPU资源紧张**：
- 高峰期：工作日 9:00-18:00
- 推荐时段：晚间、周末、节假日

**预约建议**：
- 大规模测试 (>16卡) 提前3天预约
- 紧急任务可使用高优先级队列 (费用×1.5)

### 4. 计费规则

**注意事项**：
- 按卡时计费，不足1小时按1小时计
- 作业超时会自动终止，但会继续计费
- 注意设置合理的超时时间

**计费公式**：
<pre data-wp5-code-block="COMPUTE-11" data-language="text" data-capability-status="not-executable" data-test-evidence="none">
费用 = GPU数量 × 运行小时 × 单价
     = 节点数 × 每节点GPU数 × 运行小时 × 单价
</pre>
